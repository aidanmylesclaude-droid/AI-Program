# 1.1.7 Instruction files: project `CLAUDE.md` vs global `~/.claude/CLAUDE.md` vs settings files
**Stage / Module:** 1 / 1.1 · **Status:** done · **Date taught:** 2026-11-17
**Builds on:** 1.1.1 (the folder you start in decides what loads), 1.1.5 (`.md` is for people and Claude, `.json` is strict and for programs), 1.1.6 (permission prompts).
**Source:** checked against code.claude.com/docs/en/memory and /settings on 2026-11-17.

## What you'll learn
- The two kinds of files that steer Claude Code: **instructions** (advice Claude reads) and **settings** (rules the app enforces)
- The levels each comes in (just you everywhere, one project, or personal-in-one-project), and which wins
- Which files exist on your PC right now

## Key terms
- **Instruction file (`CLAUDE.md`):** a Markdown file of guidance that's loaded into Claude's context at the start of a session. Claude *reads and tries to follow* it. It isn't enforced.
- **Settings file (`settings.json`):** a JSON file the Claude Code *app* reads. It controls things like permissions, model and theme. The app enforces it, whatever Claude decides.
- **Context:** everything Claude can see in a session: your messages, files it read, and loaded instruction files.
- **Global / user level:** files in `~\.claude\` (`C:\Users\aidan\.claude\`) that apply to *every* project on this PC.
- **Project level:** files inside one project folder that apply only there.
- **Precedence:** the order that decides which value wins when two settings files disagree.

## The problem this solves
You'll have several projects with different rules: AI-Program, trading-research, a content agent. Some rules are about *you* and belong everywhere ("explain jargon", "I use PowerShell 5.1"). Some belong to one project ("trading is research only"). And some must be *guaranteed* ("never read `.env`"), not just requested. Each kind goes in a different file.

## Explanation
**Instructions vs settings**
| | `CLAUDE.md` (instructions) | `settings.json` (settings) |
|---|---|---|
| Format | Markdown, written for people and Claude | Strict JSON, read by the app |
| What it does | Tells Claude how to behave | Controls what the app allows (permissions, model, theme) |
| Enforced? | **No.** It's context. Claude usually follows it but can get it wrong | **Yes.** A `deny` rule blocks the action even if Claude tries |
| Example | "Define every technical term" | `"deny": ["Read(./.env)"]` |

The official docs say it plainly: Claude treats CLAUDE.md files "as context, not enforced configuration."

**The levels**
| Level | Instructions | Settings | Applies to |
|---|---|---|---|
| User (global) | `~\.claude\CLAUDE.md` | `~\.claude\settings.json` | You, in every project |
| Project | `CLAUDE.md` (or `.claude\CLAUDE.md`) in the project | `.claude\settings.json` in the project | Everyone using this folder |
| Personal, one project | `CLAUDE.local.md` | `.claude\settings.local.json` | Only you, only this project (kept out of Git) |
Organizations can also add a managed level that overrides everything; not relevant to you.

**How instruction files load:** Claude Code loads `CLAUDE.md` from the folder you start in **and every folder above it**, plus your global one. They're all *added together*, not overriding each other; the one closest to where you started is read last. A `CLAUDE.md` in a folder *below* where you started loads only when Claude works in that folder.

**How settings combine:** for one value, the more specific file wins: personal-project beats project, which beats user. Lists such as permission rules are *merged* from all files.

**What exists on your PC (checked 2026-11-17)**

## Example from your projects
- "Define jargon; I'm on PowerShell 5.1": true in *every* project, so it belongs in `~\.claude\CLAUDE.md`.
- "Trading is research and education only": belongs to `trading-research\CLAUDE.md`.
- "Never read `.env`": too important to leave to advice, so it belongs in a settings `deny` rule. (Configuring that is Stage 3, Optimization Center.)
