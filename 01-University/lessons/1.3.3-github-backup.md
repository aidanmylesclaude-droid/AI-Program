## What you'll learn
- What GitHub adds on top of Git, and what a "remote" is
- Why your repos should be **private**, and what must never be pushed
- How to keep your real email out of commits
- How to push your practice repo as an online backup

## Key terms
- **GitHub:** a website that hosts copies of Git repos online. It's established and widely used. (Git = the tool on your PC; GitHub = a place to keep copies.)
- **Remote:** a copy of your repo somewhere else, usually on GitHub. Your PC keeps the full history too.
- **`origin`:** the default nickname for your main remote.
- **Push:** upload your new commits to the remote. (The opposite, **pull**, downloads new commits; that comes later.)
- **Private repo:** only you (and people you invite) can see it. A **public** repo is visible to anyone on the internet.
- **Noreply email:** an address GitHub gives you (it ends in `@users.noreply.github.com`) to put in commits instead of your real email.
- **Git Credential Manager (GCM):** comes with Git for Windows. On first use it opens a browser window for you to sign in, then stores the sign-in in Windows' credential store, so no password ever gets typed into the terminal.

## The problem this solves
Git on your PC protects you from bad *edits*. It doesn't protect you from a broken, lost or stolen laptop. A push to GitHub gives you an off-site copy. Later, GitHub is also how Claude Code on the web and other tools can reach your projects (1.2.2).

## Explanation
```
your PC (full repo)  ── git push ──►  GitHub (private copy, "origin")
```
**Three safety rules for GitHub**
1. **Private by default.** Trading strategies, content plans and supplier notes are yours. Choose **Private** for every repo unless you deliberately want it public.
2. **Never push secrets.** Once a key is pushed, assume it's leaked, even in a private repo, and even if you delete it later (it stays in history, 1.3.2). That's why **AI-Program waits until 1.3.4 (`.gitignore`)**, and today we only push the sandbox.
3. **Your sign-in is yours.** You create the account and type the password yourself in GitHub's own pages. Never paste passwords or tokens into chat or into terminal commands.

**Email privacy.** Every commit records an email (1.3.1). GitHub's **Settings → Emails → "Keep my email addresses private"** gives you a noreply address. Use that in `git config` so your real email never appears in commit history.

**Cost:** GitHub's free plan includes private repos. Check github.com/pricing if you want to confirm current limits.

## Example from your projects
Your trading-research project will live in a **private** repo, `trading-research`. Its `.env` with the market-data API key is ignored (1.3.4) and never pushed. If your laptop dies, you clone it back from GitHub and only need to re-create `.env`.

## Hands-on exercise
**Part A: account and email** (you do it, in your browser)
1. Create a free account at **github.com**. Your *username* is public, so pick something you're happy to have visible. GitHub may ask you to set up two-factor authentication. Say yes; it protects the account.
2. Go to **Settings → Emails**, tick **Keep my email addresses private**, and copy the **noreply** address it shows.
3. In PowerShell: `git config --global user.email "<the noreply address>"`, then `git config --global --list`.

**Part B: create a private repo and push** (in your browser, then PowerShell)
4. On github.com, click **New repository**. Name: `git-practice`. Choose **Private**. **Don't** add a README, .gitignore or license (we're uploading an existing repo).
5. GitHub shows a URL like `https://github.com/YOUR-USERNAME/git-practice.git`. Copy it.
6. In `exercises\sandbox-1.3.1`:
   - `git remote add origin <the URL>`
   - `git remote -v` (check it)
   - `git push -u origin main`. A browser window opens for sign-in the first time; sign in there.
7. Predict how many commits GitHub will show, then refresh the repo page.
