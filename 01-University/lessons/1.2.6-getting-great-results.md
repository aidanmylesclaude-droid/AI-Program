# 1.2.6 Getting great results: clear requests, plan mode, asking it to verify
**Stage / Module:** 1 / 1.2 · **Status:** done · **Date taught:** 2026-11-17
**Builds on:** 1.2.3 (VERIFY and stop rules), 1.2.4 (context), 1.2.5 (Plan mode).
**Source:** checked 2026-11-17 against code.claude.com/docs/en/best-practices.

## What you'll learn
- A four-part recipe for a clear request
- Why you give Claude a **check** it can run, and ask for **evidence**
- When to plan first, and how to steer when things drift

## Key terms
- **Prompt:** the message you send an AI. In agent work, it's your instructions for a task.
- **Scope:** how big the job is. What's included and what isn't.
- **Constraint:** a limit the result must respect ("don't delete anything", "no new libraries").
- **Done check:** something that comes back pass or fail, or that you can look at, which proves the job is finished.
- **Evidence:** the actual command and output (or file) that shows the check passed. It's more than the words "it worked".
- **Course-correct:** stepping in early, when an agent starts going the wrong way.

## The problem this solves
The docs name the two most common ways a session goes wrong: Claude built something different from what you had in mind (it was missing information only you have), or Claude said it was done and it wasn't (it had no way to check). Both are fixed by how you ask.

## Explanation
**1. Tell Claude what it can't see.** It can read your files. It can't read your mind. A clear request has four parts:
| Part | Question it answers | Example |
|---|---|---|
| **Goal** | What do you want, and why? | "a list of my sandbox folders, so I can decide what to delete later" |
| **Where** | Which folder or files? | "in `01-University\exercises`" |
| **Constraints** | What must *not* happen? | "don't delete or change any existing files" |
| **Done check** | How will we both know it's finished? | "show me the new file with `cat`" |

From the docs: *instead of* "fix the login bug", *try* naming where to look, the symptom, and what "fixed" looks like.

**2. Give it a check, and ask for evidence.** "Claude stops when the work looks done", say the docs. A check that comes back pass or fail lets it close the loop itself (1.2.3). Then ask for the **evidence**: the command it ran and the output. "All done" on its own tells you very little.

**3. Plan first when it's big or unclear.** Use **Plan mode** (1.2.5) so Claude explores and proposes before touching anything. If you don't know what you want yet, ask Claude to **interview you** first.

**4. Steer early.** Watch the first minute. If it drifts, stop it (`Esc` in the terminal, or the stop button in the app) and redirect. The docs advise that after **two** failed corrections you start fresh with one better prompt, rather than a third correction piled on the failed attempts. In the terminal that's `/clear`; in this app it's a new session.

**Two myths.** "Think step by step" and "be thorough" aren't magic keywords (docs). What *does* help is saying the scope you want, e.g. "be ambitious: handle the edge cases too", because only you know how much you were hoping for. And a vague prompt is fine when you're just exploring.

## Example from your projects
*Instead of* "make a TikTok script about AI."
*Try:* "Write a 45-second TikTok script (Goal) for my AI-storytelling account, in the style of `scripts/example-01.md` (Where). No real people's names, and include the platform's AI-content disclosure line (Constraints). Then count the words and confirm it's under 120 (Done check), and show me the count."

## Hands-on exercise
1. Switch the mode selector to **Plan**.
2. Send a **vague** request: `clean up my sandboxes`. Predict: will anything get deleted?
3. Rewrite it **in your own words** using the four parts. Suggested goal: an index file `exercises\SANDBOXES.md` listing each sandbox folder and what's in it.
4. Review Claude's plan. Switch back to **Auto**, tell Claude to go ahead, and check its evidence.

## Knowledge check (low pressure)
1. Name the four parts of a clear request.
2. Claude says "Done, all good!" and nothing else. What do you ask for?
3. You've corrected Claude twice on the same thing and it's still wrong. What do the docs suggest?
