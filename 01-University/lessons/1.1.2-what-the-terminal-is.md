# 1.1.2 What the terminal is: PowerShell vs Command Prompt vs bash
**Stage / Module:** 1 / 1.1 · **Status:** done · **Date taught:** 2026-11-16
**Builds on:** 1.1.1, where you used `pwd`, `cd`, `ls` and `cat`. This lesson explains what was actually reading those commands.

## What you'll learn
- The difference between a *terminal* and a *shell*
- The three shells you'll see mentioned: PowerShell, Command Prompt and bash
- How to spot a tutorial command that won't work on your computer

## Key terms
- **Terminal:** the window you type into. It only shows text and passes along what you type.
- **Shell:** the program inside the terminal that reads your command, works out what it means and runs it. PowerShell is a shell.
- **Command Prompt (cmd):** Windows' old shell from the 1980s. It still exists, but we won't use it.
- **PowerShell:** Microsoft's modern shell. Windows comes with version **5.1**. A newer version 7 exists as a separate install.
- **bash:** the standard shell on Linux and macOS (macOS now defaults to a close relative called zsh). Most online tutorials are written for it.
- **Alias:** a nickname for a command. In PowerShell, `ls` is a nickname for the real command `Get-ChildItem`.
- **Cmdlet** (say "command-let"): a PowerShell built-in command. They're named Verb-Noun, like `Get-ChildItem` or `Get-Content`.

## The problem this solves
Most AI tutorials, READMEs and videos show bash commands. Some work in PowerShell and some fail with confusing errors. If you know which shell you're in, an error like "`&&` is not a valid statement separator" stops being scary. It just means "this command was written for bash".

## Explanation
Think of the terminal as a phone and the shell as the person on the other end. The phone just carries your words. The person decides what they mean. Different shells understand different languages.

In 1.1.1, `ls`, `pwd` and `cat` worked in PowerShell. Those are bash names, but PowerShell includes **aliases** for them to make newcomers' lives easier. Under the hood they ran `Get-ChildItem`, `Get-Location` and `Get-Content`. That's also why `ls` showed a table with "Mode" and "LastWriteTime" columns. A real bash `ls` just prints names.

The aliases only go so far. Some common bash patterns fail in PowerShell 5.1:

| bash | PowerShell 5.1 equivalent |
|---|---|
| `cmd1 && cmd2` (run cmd2 only if cmd1 worked) | `cmd1; if ($?) { cmd2 }` |
| `cmd1 ; cmd2` | `cmd1; cmd2` (the same) |
| `export NAME=value` | `$env:NAME = "value"` |
| `rm -rf folder` | `Remove-Item -Recurse -Force folder` |
| `touch file.txt` | `New-Item file.txt` |

Claude Code knows you're on PowerShell 5.1 (it's written in CLAUDE.md), so it translates commands for you. You still need to know this for tutorials you read yourself.

## Example from your projects
Say a trading-research tutorial says: `pip install pandas && python analyze.py`. In your PowerShell, that line fails at the `&&` before running anything. You'd split it into two lines, or use `;`. Knowing why it failed saves you 20 minutes of confusion.

## Hands-on exercise
Use a normal PowerShell window.
1. `$PSVersionTable.PSVersion` asks PowerShell "what version are you?" The `$` marks a *variable*, a named stored value. Expect `Major 5, Minor 1`.
2. `Get-Command ls` asks "what is `ls`, really?" Expect `Alias  ls -> Get-ChildItem`.
3. `Get-ChildItem` runs the real command behind `ls`. Expect the same table you saw in 1.1.1.
4. `echo one && echo two` tries a bash pattern on purpose. Expect a red error containing `The token '&&' is not a valid statement separator`. Nothing breaks; PowerShell refuses to run the line at all.
5. `echo one; echo two` is the PowerShell way. Expect `one` and then `two` on separate lines.
