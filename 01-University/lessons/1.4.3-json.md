## What you'll learn
- The six kinds of value JSON is built from, and how they nest
- How to read a "path" to one value, like `bars → 0 → close`
- How Python turns JSON into dictionaries and lists, and the two errors you'll meet

## Key terms
- **Object** `{ }`: key → value pairs, like a Python dictionary. Keys are always in double quotes.
- **Array** `[ ]`: an ordered list of values. Counting starts at **0**: `[0]` is the first item.
- **Values:** string (`"SPY"`), number (`512.30`), `true` / `false`, `null` (nothing; it becomes `None` in Python), or another object or array.
- **Nesting:** objects and arrays inside each other. Real API responses are always nested.
- **Path:** the route to one value. `data["bars"][0]["close"]` means: in `data`, take `bars`, then item 0, then `close`.
- **Parse:** turn JSON text into program data (1.1.5). Python's `json` module does it; it's **built in**, so no venv or install is needed.
- **`KeyError`:** Python's error when you ask for a key that isn't there.
- **`JSONDecodeError`:** the error for broken JSON (like 1.1.5's missing quotes).

## The problem this solves
Almost every API (market data, YouTube analytics, Etsy listings) answers in JSON. Your agents will receive it, pick out a few values, and act on them. If you can read the structure, you can check that the agent picked the *right* values, and spot when data is missing.

## Explanation
**The example** (`market.json`, made-up data shaped like a real market-data response):
```
{                                   ← object (the whole response)
  "source": "EXAMPLE DATA ...",     ← string
  "symbol": "SPY",
  "currency": "USD",
  "bars": [                         ← array of daily "bars"
    {"date": "2026-11-16", "open": 510.10, "close": 512.30, "volume": 61200000},   ← bars[0]
    {"date": "2026-11-17", ...},                                                   ← bars[1]
    {"date": "2026-11-18", "open": 515.50, "close": 510.60, ...}                   ← bars[2]
  ],
  "next_page": null                 ← nothing (more data? no)
}
```
A **bar** is one time period of price data: open, close, volume.

**JSON → Python**
| JSON | Python | Access |
|---|---|---|
| object `{}` | dictionary | `data["symbol"]` |
| array `[]` | list | `data["bars"][0]` |
| `null` | `None` | |
| `512.30` | `512.3` (a number; the trailing zero isn't kept) | |

Compare with 1.1.5: PowerShell's `ConvertFrom-Json` displayed `512.30`, but Python shows `512.3`. Same value, different display. Don't let a format difference fool you into thinking data changed.

**Two errors, read bottom-up (1.4.2)**
- `KeyError: 'price'`: you asked for a key that doesn't exist. Check the real key names (`close`, not `price`).
- `JSONDecodeError`: the text isn't valid JSON (missing quote, extra comma).

**Data can be wrong even when it parses** (1.2.7). Valid JSON can still hold a stale date, a missing day, or an API error message instead of prices. An agent should check `date`, count the bars, and look for error fields before trusting numbers.

## Example from your projects
The trading assistant gets JSON from a market-data API, takes `bars[-1]["close"]` (the **last** bar; `-1` counts from the end), checks its `date` is the latest trading day, and only then computes an indicator. A content agent reads `views` and `averageViewDuration` from an analytics response the same way.
