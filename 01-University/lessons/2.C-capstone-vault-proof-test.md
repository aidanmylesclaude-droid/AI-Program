# 2.C Stage 2 capstone: maintenance routine and proof test
**Stage / Module:** 2 / capstone · **Status:** done · **Date taught:** 2026-11-20
**Builds on:** 1.2.4 (a new session forgets), 1.5.6 (memory in files), 1.6.4 (least privilege), 2.1–2.3.

## What you'll learn
That the vault really works as memory: a session with **no** memory of our conversations can answer from your notes and say where it found the answer.

## Key terms
- **Proof test:** a check that shows something works, with evidence, instead of assuming it.
- **Citation:** naming the exact file (and line) an answer came from, so you can check it.
- **Headless mode:** running Claude Code as a one-off command (`claude -p "question"`) with no chat window. It starts fresh, answers, and exits. (Stage 4.1 covers it properly.)
- **`--allowedTools`:** a command-line option limiting which tools that session may use. Here: read-only tools only (least privilege, 1.6.4).

## The problem this solves
A second brain is only worth having if it works when *you* (or Claude) have forgotten. This test proves it, rather than trusting that it does.

## Part 1: maintenance routine
`99-System/MAINTENANCE.md`: every session (Claude's wrap-up), weekly "vault check" (inbox, unresolved links, orphans, outdated, secrets scan), monthly review.

## Part 2: proof test (fast mode: Claude runs it)
From `AI-Program`, Claude runs a fresh headless session limited to Read, Grep and Glob, and asks:
1. "According to my notes, what is prompt injection and what is its strongest defense? Cite the file."
2. "Where did we leave off in my program? Cite the file."
Then Claude opens the cited files to check the answers match.
**Predict:** will the fresh session remember today's conversation, and what will it cite for question 1?

## Knowledge check (2 questions)
1. Why must the proof test use a *fresh* session instead of this one?
2. Why ask it to cite the file?

- Prediction: no memory of the conversation; it finds the answer in `02-Knowledge/concepts/prompt-injection.md`.
