# 1.6.3 Running without supervision: memory between sessions, error recovery, monitoring
**Stage / Module:** 1 / 1.6 · **Status:** done · **Date taught:** 2026-11-20 · *(merged: old 1.6.4–1.6.6)*
**Builds on:** 1.2.4 (a new session forgets), 1.5.6 (memory systems), 1.6.2 (checks in a chain).

## What you'll learn
The three things an agent needs when nobody is watching: a way to remember, a way to recover, and a way to tell you what happened.

## Key terms
- **Unattended / unsupervised run:** the program runs on a schedule with no human present.
- **State:** what a program remembers between runs, saved in a file or database (here `state.json`). The program itself forgets everything when it ends (like a new session, 1.2.4).
- **Retry with backoff:** try again after a failure, waiting a bit longer each time, and only a **fixed number of times**.
- **Transient vs permanent error:** a transient error might fix itself (network blip, "too many requests"); a permanent one won't (bad currency code, wrong key). Retry only transient ones.
- **Log:** a file where every event is written down with a time and a **level** (INFO = normal, ERROR = something failed).
- **Alert:** a message that reaches a human when something needs attention (later: email or notification; here: an `ALERT` line).
- **Fail loudly:** when it can't do the job, it says so clearly instead of quietly producing nothing or something wrong.

## The problem this solves
When you're watching, you notice errors. At 3am nobody does. Without memory it repeats or loses work; without recovery one network blip kills the job; without logs you can't tell what happened; without alerts you find out weeks later.

## Explanation
1. **Memory:** load state at the start, save it at the end. Same rule as this program: if it must survive, write it down (1.5.6).
2. **Recovery:** retry a few times with growing waits, then **stop**. Never loop forever (the `max_steps` idea from 1.2.3). Keep the last good data instead of overwriting it with nothing.
3. **Monitoring:** log every run, success or not. Read the log, don't trust "it probably worked" (1.2.7).
4. **Escalate:** if it gives up, a human must be told.

## Example from your projects
Content agent posting stats nightly: state remembers which videos it already counted (no double counting); retries if the platform API is busy; logs each run; alerts you if it fails two nights in a row. Stage 5 builds this for real.
