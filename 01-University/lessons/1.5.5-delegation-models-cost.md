## Part 1: Subagents
**What:** a **subagent** is a helper Claude that Claude Code starts for a side task. It works in **its own context window** and sends back a **summary**.
**When it pays off** (docs): running independent pieces at the same time; keeping long output (a wide search, a full test run) out of your main conversation (1.2.4); a fresh reviewer that didn't write the work; a helper with **fewer tools** (e.g. read-only).
**What it costs** (docs): "mostly tokens", plus sometimes time: "a fresh subagent first has to gather context your conversation already had, so it can end up *slower*." And: "You get parallelism or a fresh pair of eyes out of it, but not a smarter answer."
**Rule of thumb:** delegate big reading jobs, not small tasks. Claude Code already does this on its own (e.g. its built-in Explore agent for broad searches).

## Part 2: Picking a model
| Model (Nov 2026) | Role | Input / output price per 1M tokens (API) |
|---|---|---|
| **Haiku 5.5** | Fastest, cheapest: simple, high-volume jobs | $0.10 / $0.50 |
| **Sonnet 5.5** | Everyday work: speed plus capability | $2 / $10 |
| **Opus 5.5** | Strong reasoning; the default for complex work (this program runs on it) | $4 / $20 |
| **Fable 5.2** | Most capable widely released model: hardest, longest tasks | $8 / $40 |
All four have a 1M-token context window (1.2.4).

**Two kinds of cost:**
- **Claude Code on your plan** (what you use now): you pay the subscription; heavy use counts against your plan's **usage limits**, not a per-token bill.
- **The API** (when you build agents, Stage 4): you pay **per token**, like the table above. Input = what the model reads, output = what it writes (output costs more).

**Effort** (a setting on current models) trades thoroughness for tokens *within* one model. Anthropic's guidance: before building a complicated multi-model setup, first try the most capable model at **lower effort**; it often matches older models at high effort. Judge **cost per finished task**, not per request: a cheap call that needs retries isn't cheap.

## Part 3: Routing work
**Routing** = sending each job to the cheapest model that does it well. A simple check-links job goes to Haiku; a hard design decision goes to Opus or Fable. Start with **one** model and only add routing when you can **measure** that it saves money without losing quality (evals: Stage 4).

(Calculated by Claude on 2026-11-20 from the prices above. Fable is **80×** Haiku for the same job.) Any of these is cheap for one report; the gap matters when an agent runs hundreds of calls a day. Quality, not just price, decides: a wrong analysis is the most expensive outcome.

## Labels
Subagents: **established** (built into Claude Code). Multi-model routing: **established technique**, but **often premature**: "agent swarms" videos are mostly hype for a beginner's needs.

## Knowledge check (2 questions)
1. When does a subagent help, and when does it waste money?
2. Your agent does 1,000 simple tagging calls a day. Which model would you try first, and why?

## Answers
1. Helps: big independent reading/search jobs, parallel work, fresh review, keeping your context lean. Wastes: small tasks it has to re-learn context for. It's not smarter, just separate.
2. Haiku: cheapest and fastest. Simple, high-volume work is exactly its role; check quality on a sample before trusting it.
