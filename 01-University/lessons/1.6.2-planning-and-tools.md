# 1.6.2 Planning and tools: objective to task list, chaining tools and outside data
**Stage / Module:** 1 / 1.6 · **Status:** done · **Date taught:** 2026-11-20 · *(merged: old 1.6.2 + 1.6.3)*
**Builds on:** 1.2.3 (agent loop), 1.2.6 (goal, constraints, done check), 1.5.1 (APIs), 1.6.1 (workflow vs agent).

## What you'll learn
How an agent turns a goal into steps, what a "tool" really is, and why every link in a chain needs a check.

## Key terms
- **Objective:** the goal you give the agent ("write a report on X").
- **Plan / task list:** the objective broken into ordered steps, each with a **done check**.
- **Tool:** a function the model may ask to run. The model never runs it itself: it says "call `fetch_rates` with base=USD", **your code** runs it and hands back the result. Each tool is described by a **name**, a **description**, and its **inputs** (the API calls this the input schema).
- **Tool chaining:** one tool's output becomes the next tool's input.
- **Outside data:** anything fetched from beyond the model, such as an API, a file or a web page. It is where real, current facts come from (1.2.7).

## The problem this solves
A model alone only predicts text (1.2.1). It can't see today's prices or save a file. Tools give it hands and eyes; a plan keeps a multi-step job in order; checks stop a bad result from flowing downstream.

## Explanation
1. **Plan:** objective → small steps, each with a done check (the same habit as your requests in 1.2.6).
2. **Tools:** the model picks from a menu. Good tool descriptions matter as much as good prompts: the model only knows what the description says.
3. **Chain:** step 1's output feeds step 2. **One bad link poisons everything after it**, so check each output before passing it on.
4. **In a workflow** (1.6.1) *you* write the plan in code. **In an agent** the model writes and revises the plan while running, which is more flexible and less predictable.
5. Fewer, clearer tools beat many overlapping ones (least privilege, 1.5.3).

## Example from your projects
Trading research: objective "summarize this week's EUR/USD moves" → plan: fetch rates (tool) → calculate change (code) → explain in plain words with risks stated (model) → save report (tool). Only the "explain" step needs AI.
