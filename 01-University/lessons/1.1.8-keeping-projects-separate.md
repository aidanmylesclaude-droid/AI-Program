# 1.1.8 Keeping projects separate: one folder, one CLAUDE.md, and its own settings and secrets
**Stage / Module:** 1 / 1.1 · **Status:** done · **Date taught:** 2026-11-17
**Builds on:** 1.1.1 (start folder), 1.1.3 (`~`, `..`), 1.1.5 (`.env`), 1.1.7 (instruction and settings levels; CLAUDE.md files *above* the start folder load).

## What you'll learn
- The layout that keeps projects from mixing: side-by-side folders, never one inside another
- What each project gets of its own, and what's shared across all of them
- Where Claude Code keeps each project's history and memory on your PC

## Key terms
- **Sibling folders:** folders next to each other with the same parent, like `~\AI-Program` and `~\trading-research`.
- **Nested folder:** a folder inside another, like `~\AI-Program\trading-research`.
- **Session history / auto memory:** records Claude Code keeps *per start folder* in `~\.claude\projects\`. A different start folder means a separate record.
- **Blast radius:** how much damage one mistake or leaked secret can do. Separation keeps it small.

## The problem this solves
If projects share a folder, their rules, memory and secrets leak into each other. The trading rules would show up in content work, the content agent could read the trading API key, and Claude would mix up which project you mean.

## Explanation
**The layout**
```
C:\Users\aidan\            ← home (~). No project lives directly here.
├── .claude\               ← global: CLAUDE.md (all projects), settings.json, projects\ (history per folder)
├── AI-Program\            ← this program: own CLAUDE.md
├── trading-research\      ← later: own CLAUDE.md, own .claude\settings.json, own .env
└── content-agent\         ← later: same pattern
```

**Each project gets its own:** `CLAUDE.md` (its rules), `.claude\settings.json` (its permissions), `.env` (its secrets), and its session history and memory (automatic, by start folder).

**Shared across all projects:** only what's true everywhere: `~\.claude\CLAUDE.md` (who you are and how you learn) and `~\.claude\settings.json` (theme and personal preferences). Keep the global `CLAUDE.md` short. Everything in it loads into *every* session.

**Why siblings, not nested:** from 1.1.7, CLAUDE.md files in folders *above* the start folder load too. Put `trading-research` inside `AI-Program` and every trading session also loads the program's teaching rules and session protocol.

**Why a `.env` per project:** a key in one project's `.env` can be used only by that project. If one leaks, you replace one key, not all of them (smaller blast radius).

**Never start a project in your home folder.** Starting Claude Code in `~` makes everything below it, which is all your projects, its working area.

## Example from your projects
Your PC already shows this. `~\.claude\projects\` holds a separate folder for each place Claude Code was started, including `C--WINDOWS-System32` from when it was first started in System32, and `C--Users-aidan-AI-Program` for this program. The names are the folder path with `\` and `:` turned into `-`.
