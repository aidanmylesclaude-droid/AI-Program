# 3.3 MCP servers, connectors and APIs: choose and connect
**Stage / Module:** 3 · **Status:** done · **Date taught:** 2026-11-20
**Builds on:** 1.5.1 (APIs), 1.5.3 (MCP, connectors, least privilege), 1.6.4 (lethal trifecta), 2.2 (no Obsidian MCP), 3.1 (deny rules).

## What you'll learn
How to list what your sessions are connected to, judge each connection, and switch off what you don't use.

## Key terms
- **Connector:** an MCP server you connect once in your claude.ai account; the desktop app can hand it to Code sessions.
- **Tool count:** how many actions a connector adds. Each one is something Claude *could* do.
- **Default for new sessions:** in the desktop app, switching a connector off for a session also makes "off" the default for new sessions. You can switch it back on any time from the composer's **+ → Connectors** menu.

## The problem this solves
Every connected tool is power Claude carries into every session, and power a prompt injection could try to use (1.6.4). Least privilege: connect what the current work needs, nothing more.

**Why Gmail is the one to cut:** it has all three trifecta legs at once: your **private data** (inbox), **untrusted content** (any stranger can email you text aimed at an AI), and a **way out** (send/forward). Turning it off removes all three from Claude Code sessions. It does **not** disconnect Gmail from your claude.ai account or delete anything; switch it back on when a task truly needs it.

## APIs vs MCP vs connectors: which to use for your agents
- **Direct API call in your code** (1.5.1, capstone): best when *your program* needs data. Simple, testable, no AI involved.
- **MCP server / connector**: best when *Claude* needs a tool during a conversation.
- **Labels:** MCP **established**; claude.ai connectors **established**; random community MCP servers **experimental** (review each one in the Optimization Center first).
