**Builds on:** 1.2.1 (an LLM predicts the next token and repeats; it remembers only through files), 1.1.6 (tools, tool calls, permission prompts), 1.1.7 (CLAUDE.md).

## What you'll learn
- The three main ways an LLM is packaged for you, and what each can and can't do
- The key idea: **same kind of model, different program around it**
- How to pick the right one for a job

## Key terms
- **Chat assistant:** an app where you type and the model replies with text (the Claude app on the web, desktop or phone). By default it can't see or change files on your PC.
- **Agentic:** able to work toward a goal in a loop: plan, take an action with a tool, look at the result, decide the next step, and repeat until done.
- **Claude Code:** in the docs' words, "an agentic coding tool that reads your codebase, edits files, runs commands". It works in a folder on your computer (or on a copy of a GitHub repo in the cloud).
- **Autocomplete coding assistant:** a code-editor feature that suggests the next few lines *as you type* (for example GitHub Copilot's inline suggestions). It's established and widely used.
- **Harness:** the program wrapped around the model that gives it tools, rules and a loop. Claude Code is a harness, and so is the chat app.
- **Surface:** one of the places you can use Claude Code: terminal, desktop app (Code tab), IDE extension, or web.

## The problem this solves
Videos say "Claude", "Claude Code", "Copilot" and "AI agent" as if they were the same thing. They aren't, and picking the wrong one either wastes time (copy-pasting between a chat and your files) or gives an AI more power than the job needs.

## Explanation
| | Chat assistant | Claude Code (agent) | Autocomplete |
|---|---|---|---|
| You give it | A message | A goal, in a project folder | Nothing; it watches you type |
| It gives back | Text (and sometimes files or charts it made) | Changes on disk: files read and edited, commands run | A grey suggestion you accept with Tab |
| Sees your PC's files? | No, unless you paste or upload them | Yes, in its working folder, with permission prompts | Only the code files open in your editor |
| Runs commands on your PC? | No | Yes, after you allow them | No |
| Works in a loop until done? | One reply per message | **Yes**: plan → act → check → repeat | No |
| Reads `CLAUDE.md`? | No | Yes, every session | No |

**The key idea.** The model inside can be the same kind of LLM. The difference is the **harness**: what tools it gets and whether it loops. LLM + tools + a loop + files for memory is roughly what "agent" means. That's the thread that runs through the rest of this program.

**Autocomplete is 1.2.1 in its purest form.** It predicts the next tokens of *your code*, right where your cursor is.

**Honest caveats.**
- The lines are blurring. The chat app has its own tools (such as web search and connectors, depending on what's turned on), and many autocomplete products have added chat and "agent modes". Treat the three columns as **modes of working**, not brand names.
- Claude Code on the **web** runs on Anthropic's computers, working on a GitHub repo, not on your PC. That's Module 1.3 territory.
- On Windows without Git, Claude Code runs commands in PowerShell (the docs say so). That's why every command I've run for you has been PowerShell.

## Example from your projects
- "Explain what the RSI indicator measures" → **chat**. It's just an explanation, and no files are needed.
- "Rename my 30 draft video scripts to `script-01.md` … `script-30.md`" → **Claude Code**. It needs to see and change files.
- "While writing a Python script, finish this line" → **autocomplete**.
- "Every morning, fetch prices from a data API and save a report" → an **agent** (Claude Code now; later something you build), plus a data tool.
