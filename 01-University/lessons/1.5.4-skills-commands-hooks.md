## What they are
| | What it is | Loaded / runs when | Enforced? | Label |
|---|---|---|---|---|
| **CLAUDE.md** (recap) | Standing instructions | Every session, in full | No: advice | Established |
| **Skill** | A folder with a `SKILL.md`: a **reusable playbook** (instructions, optionally scripts and reference files) for one kind of task | Its short description is always visible; the **full body loads only when used** ("long reference material costs almost nothing until you need it") | No: advice | Established |
| **Slash command** | Typing `/name` in the prompt. Built-ins like `/mcp`, `/compact`; **custom commands are now skills** ("Custom commands have been merged into skills") | When you type it | n/a | Established |
| **Hook** | A **script the harness runs automatically** at set moments (e.g. `PreToolUse`, before a tool call; `Stop`, when Claude tries to finish) | On the event, every time | **Yes**: "certain actions always happen rather than relying on the LLM to choose" | Established |

**Where skills live:** personal `~\.claude\skills\<name>\SKILL.md` (all projects) or project `.claude\skills\<name>\SKILL.md` (this project, can be committed to Git). Same levels as CLAUDE.md (1.1.7).

**How a hook blocks:** a `PreToolUse` hook script exits with code **2** → the action is blocked and Claude gets the reason. The docs' own example: stop Claude editing `.env` or anything in `.git/`.

## Which one to use
- A rule for every session → **CLAUDE.md**
- A procedure you repeat sometimes ("write a TikTok script our way", "review a tool") → **skill** (keeps CLAUDE.md short, costs context only when used)
- Something that must **always** or **never** happen → **hook** or a settings `deny` rule
- Hooks run real commands on your PC automatically, so only add hooks you understand (the 1.4.1 safety-scan mindset).
