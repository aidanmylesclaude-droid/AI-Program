## What it is (four words that get mixed up)
| Term | What it actually is | Label |
|---|---|---|
| **MCP** (Model Context Protocol) | An open **standard**: an agreed way for AI apps to talk to outside tools and data. The official analogy: "like a USB-C port for AI applications." | **Established** |
| **MCP server** | A program that speaks MCP and offers **tools** for one app (e.g. "search my email", "create a Notion page"). It runs locally on your PC, or remotely at a URL. | Varies per server: some official and solid, many hobby projects |
| **Connector** | Anthropic's name for a **ready-made MCP server** you switch on in claude.ai (from the Anthropic Directory). Per the docs, connectors you set up in claude.ai "also appear in Claude Code." | Established (official ones) |
| **Integration** | A general word for "two systems connected", by any method: an API script, MCP, Zapier… **Not a specific technology.** | n/a |
| **Plugin** | A bundle for Claude Code that can package several add-ons together: skills, commands, hooks, agents and MCP servers. | Established mechanism; quality depends on who made it |

## How it relates to APIs (1.5.1)
```
Claude ──(MCP)──► MCP server ──(the app's API + your key)──► Gmail / Notion / a market-data service
```
An **API** is the service's own doorway. An **MCP server** is an *adapter* that turns those API calls into **tools** Claude can call, the same kind of tool calls you've been reading since 1.1.6. Without MCP, Claude can still use an API by writing and running a script (like `fx_rates.py`).

## Why it exists
So you stop copy-pasting between apps and Claude, and so one connector works across many AI apps ("build once, integrate everywhere").

## The risks (the important part)
- **Every connector is power you hand over.** A Gmail connector with a "send" tool can send email as you.
- **Prompt injection:** the docs warn that "Servers that fetch external content can expose you to prompt injection risk": a web page or email can contain hidden instructions aimed at the AI.
- **Least privilege:** connect only what the current project needs, and switch off what it doesn't.
- **Third-party servers are code you run** (local ones especially): the 1.4.1 and 1.4.2 rules apply. Check who made it, and read before you install.

## Mostly hype
"Install these 20 MCP servers to 10× your AI" videos. More connectors means more risk and more clutter. Add one only when a real task needs it (an Optimization Center review first; setup is Stage 3.3).

## Knowledge check (2 questions)
1. In one line each: MCP vs MCP server vs connector.
2. Why not connect every MCP server you see recommended in a video?

## Answers
1. MCP is the standard; an MCP server is a program that offers tools through it; a connector is a ready-made MCP server you enable in claude.ai.
2. Each one is more power and more risk (sending, deleting, prompt injection), plus clutter. Connect only what a real task needs (least privilege).
