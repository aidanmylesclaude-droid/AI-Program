## What you'll learn
- What version control is, and why it's your safety net when agents edit files
- How to install Git from the official source
- The first four Git commands: `init`, `status`, `add`, `commit` (plus `log` to look back)

## Key terms
- **Version control:** a system that saves snapshots of a project over time, so you can see what changed, when, and go back.
- **Git:** the most widely used version control tool. Free, established, runs on your PC.
- **Repository (repo):** a project folder that Git is tracking. Git keeps its history in a hidden `.git` folder inside.
- **Commit:** one saved snapshot, with a short message saying what changed and why.
- **Staging (`git add`):** choosing which changes go into the next commit.
- **Working directory:** the files as they are right now on disk, possibly with changes not yet committed.
- **PATH:** the list of folders Windows searches when you type a program's name. Installers add to it, and a terminal only sees the new PATH after you reopen it.
- **GitHub:** a website that stores copies of Git repos online (lesson 1.3.3). Git and GitHub are not the same thing.

## The problem this solves
`rm` can't be undone (1.1.4). Claude Code's checkpoints cover files Claude edits with its file tools, but the docs say changes made by commands aren't restored. An agent working overnight could make 50 changes you didn't want. With Git, every commit is a snapshot you can compare against and return to, whoever made the mess.

## Explanation
**The idea in one picture**
```
edit files ──► git add (choose changes) ──► git commit -m "message" (save snapshot)
                                                   │
                     history: snapshot 1 ─ snapshot 2 ─ snapshot 3 ...
```
- `git init`: turn the current folder into a repo (do it once per project).
- `git status`: what's changed since the last commit? (safe; it only looks)
- `git add <file>`: stage a change for the next commit.
- `git commit -m "message"`: save the snapshot.
- `git log --oneline`: list the snapshots.

**Commit messages matter.** "Add RSI notes" helps future-you and agents. "stuff" doesn't.

**Installing: the two routes** (from git-scm.com)
| Route | Maintained by | Notes |
|---|---|---|
| **Official installer** (`Git-2.56.1-64-bit.exe`) | the Git for Windows project | **Recommended.** Official source; many screens, but defaults are fine |
| `winget install --id Git.Git -e --source winget` | *not* the Git project (the page says so) | One command; may lag behind the latest version |

Two installer screens worth changing from the default, if your installer shows them:
- **Default editor used by Git:** pick **Notepad** (the built-in default, Vim, is confusing for beginners).
- **Name of the initial branch:** choose to override it, and type **main** (the modern standard name).
Keep every other screen on its default.

**What changes for Claude Code:** the docs say that with Git for Windows installed, Claude Code can use a Bash tool, not only PowerShell. You'll recognize Bash from 1.1.2. Claude will say which shell it's using.

## Example from your projects
The content agent rewrites your 30 scripts overnight and makes them worse. Without Git: they're gone. With Git: `git status` shows what changed, `git diff` (next lesson) shows how, and you restore yesterday's snapshot. Same for the trading research notes.

## Hands-on exercise
**Part A: install** (you do it, after you've decided to)
1. In your browser, go to **git-scm.com** and open the Windows download page. Download the **x64 Setup** (`Git-2.56.1-64-bit.exe` or newer).
2. Run it. Windows will ask for permission (that's an install, so it's expected). Keep defaults, except Notepad as the editor and **main** as the branch name.
3. **Close and reopen** PowerShell (new PATH), then predict, then run `git --version`.

**Part B: tell Git who you are** (stored on your PC, attached to each commit)
- `git config --global user.name "Your Name"`
- `git config --global user.email "you@example.com"`. Use an email you're happy to have attached to commits; if you later publish to GitHub it can become public (1.3.3 covers GitHub's private "noreply" address).

**Part C: first commit** in a practice repo, `exercises\sandbox-1.3.1`
1. `cd ~\AI-Program\01-University\exercises`, `mkdir sandbox-1.3.1`, `cd sandbox-1.3.1`
2. `git init`
3. `Set-Content notes.txt "version 1"`
4. Predict, then `git status`
5. `git add notes.txt`, then `git status` again
6. `git commit -m "Add first note"`
7. `git log --oneline`
