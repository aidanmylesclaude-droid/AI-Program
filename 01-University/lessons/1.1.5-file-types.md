# 1.1.5 File types you'll meet: `.md`, `.txt`, `.json`, `.yaml`, `.env`, `.py`

## What you'll learn
- What a file extension really is, and what it isn't
- The six text file types you'll keep meeting in Claude Code, agent projects and tutorials, and what each one is for
- Why API keys live in `.env` files

## Key terms
- **File extension:** the letters after the last dot in a file name (`.json`). It's a label that tells people and programs what's inside. It does not change what's inside.
- **Plain text:** a file that is just characters, readable with `cat`. All six types here are plain text.
- **Structured data:** text arranged in a strict pattern so a program can pull out exact values, for example "the price of SPY".
- **Key / value:** a name and the thing it stands for, like `symbol: SPY`. Most structured formats are built from these pairs.
- **Parse:** for a program, to read structured text and turn it into values it can use. If the text breaks the pattern, parsing fails.
- **API key:** a secret password that lets a program use a paid or private online service (for example a market-data service). Anyone who has it can use your account.
- **Script:** a file of instructions for a program to carry out. `.py` files are Python scripts.

## The problem this solves
Every tutorial, repo and Claude Code setting uses these files. If you don't know a `.json` from a `.yaml`, you can't tell which file to edit, what will break, or which file must never be shared.

## Explanation
| Extension | Name | What it's for | Who reads it | Example in your world |
|---|---|---|---|---|
| `.txt` | Plain text | Anything, with no formatting | People | A quick note |
| `.md` | Markdown | Notes with light formatting (`#` heading, `-` bullet) | People and Claude | All your program files, your future Obsidian vault |
| `.json` | JSON | Structured data. Strict: quotes, commas and braces must be exact | Programs | What a market-data API sends back; Claude Code's `settings.json` |
| `.yaml` / `.yml` | YAML | Structured data that's easier for people to read. Indentation matters | Programs, edited by people | Config files; the `---` block at the top of an Obsidian note |
| `.env` | Environment file | Secrets and settings as `NAME=value` lines | Programs | `MARKET_API_KEY=...` for the trading assistant |
| `.py` | Python | A script: instructions to *run* | The Python program | A script that pulls prices and saves a report |

Three points:
1. **The extension is a label, not a lock.** Renaming `notes.txt` to `notes.py` doesn't change a single character inside. It only changes which program Windows *suggests* opening it with.
2. **JSON and YAML can hold the same data.** JSON is stricter and easier for programs to read. YAML is easier for people to read.
   ```
   JSON:  {"symbol": "SPY", "price": 512.30}
   YAML:  symbol: SPY
          price: 512.30
   ```
3. **`.env` isn't protected by anything special.** It's plain text that anyone with the file can read. The protection is a habit: never share it, never paste it into notes or chats, and (from Lesson 1.3) tell Git to ignore it so it never gets uploaded.

**Safety rule:** opening or `cat`-ing any of these files is harmless. *Running* a `.py` file executes its instructions, so only run scripts you understand or trust.

## Example from your projects
The trading assistant would keep `MARKET_API_KEY=...` in `.env`, run a `.py` script that asks a market-data service for prices, receive **JSON** back, and save a summary as a **Markdown** note in your vault. That's four of the six types in one small workflow.

## Hands-on exercise
Work in `~\AI-Program\01-University\exercises\sandbox-1.1.5`. Python on this PC runs with **`py`** (plain `python` only opens a Microsoft Store message).
1. `mkdir sandbox-1.1.5` (from `exercises`), then `cd sandbox-1.1.5`
2. `Set-Content hello.txt 'print("hello from Python")'`, then `cat hello.txt` shows the text.
3. Predict, then run: `py hello.txt`. **It works** and prints `hello from Python`. Python doesn't care about the label.
4. `Set-Content stock.json '{"symbol": "SPY", "price": 512.30}'`, then `cat stock.json | ConvertFrom-Json` shows a table with `symbol` and `price` as separate columns. The program has pulled the values out of the text.
5. Predict, then run: `Set-Content broken.json '{"symbol": SPY}'`, then `cat broken.json | ConvertFrom-Json` gives a red error: `Invalid JSON primitive: SPY`. JSON text values need quotes.
6. `Set-Content .env 'MARKET_API_KEY=fake-key-123'`, then `ls` and `cat .env`. It's just text. Use fake values in practice, always.
(The example price is made up.)
