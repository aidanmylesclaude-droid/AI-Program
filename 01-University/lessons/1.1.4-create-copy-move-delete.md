# 1.1.4 Creating, copying, moving and safely deleting files
**Stage / Module:** 1 / 1.1 · **Status:** done · **Date taught:** 2026-11-17
**Builds on:** 1.1.3 (`cd`, `..`, `~`, Tab, `ls <path>`) and 1.1.2 (aliases, `Get-Command`). This is the first lesson where your commands *change* things on disk.

## What you'll learn
- How to make folders and files, copy them, move them and rename them from the terminal
- Why deleting in the terminal is more dangerous than deleting in File Explorer, and how to preview a delete before doing it

## Key terms
- **Create:** make a new, empty folder or file.
- **Copy:** make a second, identical file. The original stays where it was.
- **Move:** put a file somewhere else. The original is gone from its old spot.
- **Rename:** in the terminal, this is just a move to a new name in the same folder.
- **Sandbox:** a throwaway practice folder where mistakes can't hurt anything important.
- **Overwrite:** replacing an existing file's contents with something new. The old contents are lost.
- **`-WhatIf`:** a PowerShell parameter that *describes* what a command would do without doing it.
- **Recycle Bin:** File Explorer's safety net for deleted files. **Terminal deletes skip it.**

## The problem this solves
Agents create, copy, move and delete files all the time. Your content agent will save scripts and video files, and your trading assistant will save research notes. You need to be able to do these four things yourself, and you need to know which of them can lose work, so you can judge what an agent is about to do when it asks for permission.

## Explanation
| Action | PowerShell command | Alias you can type | Danger |
|---|---|---|---|
| Make a folder | `New-Item -ItemType Directory` | `mkdir` | None |
| Make a file with text in it | `Set-Content` | — | **Overwrites** if the file already exists |
| Copy | `Copy-Item` | `cp`, `copy` | **Overwrites** the destination without asking |
| Move or rename | `Move-Item` | `mv`, `move` | Low. It refuses if the destination already exists. |
| Delete | `Remove-Item` | `rm`, `del` | **Permanent.** No Recycle Bin, no undo. |

Two habits make deleting safe:
1. **Preview first.** Add `-WhatIf` and PowerShell tells you exactly what it would remove.
2. **Be specific.** Delete one named file, not a pattern. A pattern like `*` ("everything") is how people wipe whole folders.

## Example from your projects
Your content agent writes `script-v1.txt` and later copies it to `script-final.txt`. If a later step copies a new draft over `script-final.txt`, the old final version is silently gone. That's why a well-built agent saves to *new* names (`v2`, `v3`) rather than overwriting, and why Claude Code asks you before running delete commands.

## Hands-on exercise
Work in the sandbox only: `~\AI-Program\01-University\exercises\sandbox-1.1.4`.
1. `cd ~\AI-Program\01-University\exercises`
2. `mkdir sandbox-1.1.4` shows a small table with one line starting `d-----`, the new folder.
3. `cd sandbox-1.1.4`
4. `Set-Content notes.txt "My first file"` shows nothing. Silence means it worked.
5. `cat notes.txt` shows `My first file`.
6. `cp notes.txt backup.txt` then `ls` shows two files.
7. `mkdir old` then `mv backup.txt old` then `ls`, then `ls old`. `backup.txt` has moved into `old`.
8. `mv notes.txt idea.txt` then `ls`. This is a rename: `notes.txt` is now `idea.txt`.
9. `rm old\backup.txt -WhatIf` prints a line starting `What if: Performing the operation "Remove File"`. Then `ls old` shows the file is still there.
10. `rm old\backup.txt` then `ls old` shows nothing: the folder is empty. Check your Recycle Bin: the file is not there either.
