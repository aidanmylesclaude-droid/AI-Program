# 1.1.6 How Claude Code runs commands for you, and how to read what it ran
**Stage / Module:** 1 / 1.1 · **Status:** done · **Date taught:** 2026-11-17
**Builds on:** 1.1.1 (working directory), 1.1.2 (shell, PowerShell 5.1, `&&`), 1.1.4 (`rm`, `-WhatIf`, overwriting), 1.1.5 (`py`, running vs reading).

## What you'll learn
- What actually happens when Claude "runs a command"
- How to find and read a command Claude ran, and its output
- How to spot a risky command before you approve it

## Key terms
- **Tool:** an action the Claude Code app lets the model take, such as "run a PowerShell command", "read a file" or "edit a file". The model asks; the app does it.
- **Tool call:** one use of a tool, for example one command Claude ran. In the app it shows as a collapsible line you can click open.
- **Output:** the text a command prints. Claude reads it the same way you read your terminal.
- **Permission prompt:** the app pausing to ask you before Claude does something, so you can allow or deny it.
- **Permission mode:** a setting for how often the app asks first. It's chosen in the picker by the message box.
- **`-Recurse`:** a parameter meaning "this folder *and everything inside it*".
- **`-Force`:** a parameter meaning "do it even where you'd normally refuse or ask".

## The problem this solves
An agent is only as safe as the person approving its actions. If you can't read what Claude is about to run, approving a permission prompt is a blind "yes". Reading commands is the skill that makes it safe to let an agent work on your computer.

## Explanation
**What happens, step by step**
1. Claude (the model) decides a command would help, and writes it out as a tool call.
2. The Claude Code app checks your permission mode. If needed, it asks you.
3. The app runs the command in **PowerShell 5.1 on your PC**, starting in the session's folder (`C:\Users\aidan\AI-Program`).
4. The output goes back to Claude, which reads it and decides what to do next.

Claude doesn't type into your terminal window or see your screen. It works through the app, one tool call at a time. Everything from 1.1.1–1.1.5 still applies: same shell, same working-directory rule, same `&&` limitation, same "`rm` is permanent".

**Reading a command: three questions**
1. **What's the command?** The first word (`Get-ChildItem`, `Remove-Item`, `py`...).
2. **What does it touch?** The path. Is it inside `AI-Program`, or somewhere else?
3. **Any danger words?** `Remove-Item`/`rm`/`del`, `-Recurse`, `-Force`, `*`, `Set-Content` on an important file, system folders, or downloading and running something from the internet.

**Reading vs changing.** Commands that only *look* (`ls`, `cat`, `Get-Command`, `py --version`) are low risk. Commands that *change* things (create, overwrite, move, delete, install, run a script) are the ones to read carefully.

**Be honest about the limits.** Claude can misread a situation or make a mistake. The permission prompt is your checkpoint, and reading the command is how you use it.

## Example from your projects
Earlier today Claude ran `py --version` to check which Python you have, found 3.15.2 (not the 3.13 written in `CLAUDE.md`), and found that plain `python` only opens a Microsoft Store message. It then corrected `CLAUDE.md`. That's the whole loop: run → read output → act on it. A content agent does the same thing at a bigger scale: run a script that renders a video, read whether it succeeded, then upload it or retry.

## Answers
- a. **Allow.** It only lists a folder inside your project.
- b. **Allow only if you asked for it.** It permanently deletes the whole sandbox folder and everything inside it, without asking (`-Recurse -Force`), and nothing goes to the Recycle Bin.
- c. **Deny unless you asked for it.** It replaces your whole rulebook with two words (1.1.4: `Set-Content` overwrites).
- d. **Deny.** `Invoke-WebRequest` downloads a file from the internet, and `Invoke-Expression` runs text as commands, so it runs unknown code from the web without you seeing it. This pattern is common in tutorials and is a classic way to get malware.
