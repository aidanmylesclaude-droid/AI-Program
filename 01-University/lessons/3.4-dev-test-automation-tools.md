## What you'll learn
Which developer tools earn a place now, which wait for a later stage, and which to skip. And your first automated test.

## Key terms
- **Automated test:** a small piece of code that checks other code gives the right answer, and can be re-run in seconds after every change.
- **pytest:** the most widely used Python testing tool. Finds functions named `test_...` and runs them.
- **assert:** "this must be true, or the test fails".
- **Linter / formatter:** tools that flag likely mistakes / tidy code layout automatically (e.g. Ruff).
- **Custom subagent:** a subagent you define yourself (`.claude/agents/`), with its own instructions and tools.
- **IDE / code editor:** an app for reading and editing code (e.g. VS Code).

## The problem this solves
"It worked when I ran it" isn't proof it still works after a change. Tests are the habit that makes Stage 4 evals possible: an eval is a test for an AI's output.

## Adopt / later / skip (2026-11-20)
| Tool | Label | Verdict | Why |
|---|---|---|---|
| **pytest** | Established, free | **Adopt now** (per project venv) | Foundation for Stage 4 evals; tiny to learn |
| Git (have) | Established | In use | Already your undo button |

| Built-in subagents (have) | Established | In use, automatically | Claude Code uses them for wide searches |
| Ruff (linter/formatter) | Established, free | Later (Stage 4) | Useful once you write more code yourself |
| VS Code | Established, free | Optional, Stage 4 | Obsidian + Claude cover reading for now |
| Custom subagents (`.claude/agents/`) | Established | Later (Stage 4–6) | Only when a repeated side job needs its own tools/instructions (1.5.5) |

| "AI dev" tool bundles / agent frameworks | Mostly hype for you now | Skip | 1.5.6 skip list |
