## What you'll learn
- The stages of the loop every agent runs, and what happens in each
- Where the loop goes wrong, and how a good agent recovers
- Why agents need a **stop rule** and a **verify step**

## Key terms
- **Goal:** what the agent is trying to achieve. It's the reason the loop exists, and the test for "am I done?".
- **Observe:** read the result of an action: the output, an error, or a changed file.
- **Error recovery:** noticing that an action failed, working out why, and trying something different instead of repeating the mistake or giving up.
- **Verify:** checking that the result is actually right *before* saying "done".
- **Stop rule:** a condition that ends the loop: the goal is met, the agent is out of options, or it has hit a step limit.
- **Step limit:** a maximum number of loop rounds, so a confused agent can't run (and spend money) forever.
- **Human checkpoint:** a point where a person approves before the agent acts. Permission prompts are one.

## The problem this solves
A chatbot answers once. An agent keeps going, and that's powerful but risky: it can wander, repeat a failing action, or announce "done" when it isn't. Knowing the loop lets you design agents that recover and stop properly, and lets you spot when one is going wrong.

## Explanation
```
        GOAL
          │
          ▼
   ┌─► READ / GATHER CONTEXT   (files, CLAUDE.md, earlier results)
   │      │
   │      ▼
   │    PLAN                   (what's the next useful step?)
   │      │        ◄── human checkpoint: permission prompt
   │      ▼
   │    ACT                    (one tool call: run a command, read or edit a file, search)
   │      │
   │      ▼
   │    OBSERVE                (output, error, changed file)
   │      │
   │      ▼
   └── DECIDE: done? ── no ─┘
          │ yes (after VERIFY)
          ▼
        ANSWER / STOP
```

**Where it goes wrong, and the fix**
| Failure | Example from today | Good recovery |
|---|---|---|
| Missing or wrong context | A relative path run from the wrong folder | Notice the error, use the right path |
| A tool error | `python` → "Python was not found" | Read the error, try `py` instead (Claude did this when preparing 1.1.5) |
| Misreading the output | "10 lesson files" isn't "10 lessons done" | Check a better source (the `[x]` marks) |
| Repeating the same failing step | Running `python` again and again | Change the approach, or stop and ask |
| Saying "done" too early | Answering from memory without checking | **Verify** first |
| Never stopping | Looping on an impossible goal | A **step limit**, then report failure honestly |

**The LLM's role.** In a real agent, the model does the PLAN and DECIDE stages by predicting the next useful step (1.2.1), and the harness carries out the ACT stage (1.2.2). Because the model's decisions are predictions, they can be wrong. That's why **observe** and **verify** matter so much: they check the model's guesses against reality.

## Example from your projects
**Content agent:** GOAL "publish today's short" → READ last week's analytics → PLAN a topic → ACT write the script, make the video → OBSERVE does it meet length and policy rules? → DECIDE fix or continue → human checkpoint before upload → ACT upload → OBSERVE did the upload succeed? → stop. Tomorrow's loop starts by *reading* today's views. That's how it "learns", through files (1.2.1).

**Trading research assistant:** GOAL "find setups matching my rules" → ACT fetch data → OBSERVE did the data arrive, and is it today's? → ACT compute indicators → VERIFY spot-check a value → ANSWER with risks stated. No step ever places a trade.
