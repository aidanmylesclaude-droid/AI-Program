## What you'll learn
- What a context window is, and what fills it during a Claude Code session
- What happens when it gets full (compaction), and what can get lost
- Why "bigger" isn't automatically "better" (context rot)
- Why this program keeps rules and progress in files

## Key terms
- **Context window:** everything the model can see while writing its next reply: instructions, your messages, its replies, files it read, command output. The official docs call it the model's "working memory". It's separate from the training data (1.2.1).
- **Session:** one conversation. Each new session starts with a fresh, empty context window.
- **Compaction:** when the window is nearly full, Claude Code summarizes older parts of the conversation to make room. The summary keeps the gist, but "detailed instructions from early in the conversation may be lost" (official docs).
- **Context rot:** the docs' name for accuracy and recall getting worse as the context grows very large. More context isn't automatically better.
- **Pinned context:** information loaded fresh at the start of every session, such as `CLAUDE.md`, rather than said once in chat.

## The problem this solves
If you tell an agent an important rule once, in chat, it can disappear: when the session ends, and sometimes even within a long session after compaction. Agents that run every day (content, trading research) must get their rules and memory from files, or they'll drift.

## Explanation
**What fills the window in Claude Code** (from the docs): your conversation history, file contents, command outputs, `CLAUDE.md`, auto memory, loaded skills and system instructions. Every `cat`, every tool result and every long reply takes space.

**How big?** Current Claude models (including the one teaching you) have a **1-million-token** window, according to the docs as of 2026-11-17. That's a lot, but long agent sessions with big files and outputs still fill it, and quality can drop well before it's full (context rot). So **keep context lean and relevant**: that's called *curating context*.

**When it fills:** Claude Code compacts automatically. You keep going, but early details may now exist only as a summary.

**Between sessions:** nothing carries over in the window. "Sessions are independent", say the docs. What carries over is what's in files: `CLAUDE.md` (loaded every time), `PROGRESS.md` (which our session protocol says to read first), and lesson files.

**The design rule this program follows:** *If it must survive, write it down.* Chat is for working. Files are for remembering.

## Example from your projects
**Content agent:** "Never post more than 2 videos a day per account (platform spam rules)" must live in its `CLAUDE.md` or settings, not in a chat message from week one. Otherwise, after a few weeks of daily sessions it's gone, and the account risks a ban.
**Trading research:** a rule like "research only, never place trades" is safety-critical. It belongs in the project's instruction file *and* is enforced by not giving the agent any trading tools at all.
