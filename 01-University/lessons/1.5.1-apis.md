## What it is
An **API** (Application Programming Interface) is a doorway a service opens *for programs*: instead of a web page for people, it answers requests with data (usually JSON).

## What it does / why it exists
It lets your scripts and agents get data or take actions in another service without a person clicking around: prices, video analytics, product listings. Every one of your three agent ideas depends on APIs.

## Key terms
- **Endpoint:** the web address of one API function, e.g. `https://api.frankfurter.dev/v2/rates`.
- **Request:** your program's message to the API. **GET** = "send me data" (read-only). **POST** = "here's data, do something with it" (it changes or sends something), so read POSTs carefully (1.4.1).
- **Parameters:** options added to the request, e.g. `base=USD&quotes=EUR,GBP,JPY`. They appear after `?` in the URL. (`%2C` is a comma, written in the safe URL form.)
- **Response:** what comes back: a **status code** plus a **body** (usually JSON).
- **Status code:** a number saying how it went. **200** OK · **400/422** your request was wrong · **401/403** missing or bad key/permission · **404** not found · **429** too many requests (rate-limited) · **500+** the service failed.
- **Rate limit:** a cap on how often you may call. Agents that loop must respect it.
- **Terms of use:** the rules for using the API's data. Always read them before building on an API.

## How it works
```
your script ── GET /v2/rates?base=USD&quotes=EUR,GBP,JPY ──►  Frankfurter API
            ◄── 200 + JSON [ {date, base, quote, rate}, ... ] ──
```
A careful script then **checks** the response before trusting it (1.4.3):
1. Status code is 200? 2. Got everything asked for? 3. How fresh is the data?

## When you'd need it / does it matter for your projects?
Yes, for all three: market data (trading), platform analytics and uploads (content), listings and supplier data (e-commerce). **Established** technology.

## Important limits
- These are **reference rates**, published once or a few times a day. They're **not live trading prices**. Real trading data needs a proper market-data provider (and usually a key, 1.5.2).
- Research and education only (program safety rule): an API that *reads* prices is fine; nothing here places trades.

## Answers
Exercise: step 1's install comes from pip's cache; step 2 flags `import requests` and `requests.get(` (GET = read-only; it sends only `base` and `quotes`, nothing secret); step 3 → 200, 3 of 3, 0 days old on a weekday (it may be older on weekends or holidays); step 4 → **422**, `invalid currency: ABC` (a 4xx: your request was wrong).
1. GET asks for data; POST sends data or triggers an action. Read POSTs closely: what's sent, and where?
2. Too many requests (rate limit). Wait and retry later, slower. Don't hammer the API.
3. No. They're reference rates published a few times a day, not live tradable prices, and this program is research and education only.
