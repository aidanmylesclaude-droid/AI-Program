## Key terms
- **Comment:** a line starting with `#`. Notes for humans; Python ignores it.
- **Import:** borrowing ready-made tools. `import random` loads Python's built-in random-number tools. (Built-in means nothing to install. Installed extras are 1.4.2.)
- **Variable:** a name holding a value: `word = "the"` stores the text `the` under the name `word`.
- **String:** text in quotes, `"the"`. Triple quotes `"""..."""` allow several lines.
- **List:** an ordered collection, `["the", "market", "opened"]`.
- **Dictionary:** a lookup table of key → value, like `{"market": 3, "video": 2}`.
- **Function call:** `name(...)` runs a tool, e.g. `print("hi")` shows text; `text.split()` cuts text into a list of words.
- **Loop:** repeat a block. `for x in ...:` goes through each item; `range(8)` means "8 times".
- **Indentation:** the spaces at the start of a line. In Python they show which lines belong *inside* a loop or `if`. They're not decoration.
- **`if` / `break`:** make a decision; `break` jumps out of the loop (a stop rule, 1.2.3).

## The problem this solves
Agents write and run scripts constantly. If you can't read one, you can't judge it: is it doing what you asked, and is it safe to run? You don't need to write code from scratch to answer those questions.

## Explanation
**The four questions for any script**
1. **What does it say it does?** Read the comments first.
2. **What does it read?** (inputs: text in the file, files, the internet, keys)
3. **What does it change or send?** (writing or deleting files, network calls). This is the safety scan.
4. **Where does it stop?** (loops, limits, `break`)

**Safety scan, quick version:** search the script for words that signal changes or network access:
`open(` (files), `write`, `remove`/`unlink`/`rmtree` (deleting), `requests`/`urllib` (internet), `subprocess`/`os.system` (running other programs). Finding one isn't proof of harm; it tells you *where to read carefully*. (Lesson 1.2.7 applies: a search can miss things, so for anything important, read it all.)

**`tiny_predictor.py` walkthrough** (your 1.2.1 script)
| Lines | Code (shortened) | Plain English |
|---|---|---|
| 1–4 | `# tiny_predictor.py: ...` | Comments: what it does, and "It changes no files" |
| 5–6 | `import random` / `from collections import Counter, defaultdict` | Borrow built-in tools: random picks, and counting tables |
| 9–13 | `text = """ the market opened ... """` | A variable holding the training text (a multi-line string) |
| 16 | `words = text.split()` | Cut the text into a list of words |
| 17 | `follows = defaultdict(Counter)` | An empty lookup table: word → counts of what came next |
| 18–19 | `for current, nxt in zip(words, words[1:]):` / `follows[current][nxt] += 1` | **Training:** for each pair of neighbouring words, add 1 to that count |
| 21–22 | `print("After 'the', ...", dict(follows["the"]))` | Show what it learned |
| 26–27 | `word = "the"` / `sentence = [word]` | **Start word**, and a list to build the sentence in |
| 28 | `for _ in range(8):` | Repeat **at most 8** times: a step limit (1.2.3) |
| 29–31 | `options = follows[word]` / `if not options: break` | Look up what can follow; if nothing, stop |
| 32 | `word = random.choices(..., weights=...)[0]` | **Sampling:** a weighted random pick (1.2.1) |
| 33–35 | `sentence.append(word)` / `if word == ".": break` | Add the word; stop at a full stop: a stop rule |
| 36 | `print("Generated:", " ".join(sentence))` | Join the words with spaces and show them |

Answers to the four questions: (1) a toy next-word predictor; (2) only the text inside the script; (3) **nothing**, it only prints; (4) after 8 words or at a `.`.
