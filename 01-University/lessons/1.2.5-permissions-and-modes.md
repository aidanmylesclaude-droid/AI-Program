# 1.2.5 Permissions and modes: what Claude may do on your computer
**Stage / Module:** 1 / 1.2 · **Status:** done · **Date taught:** 2026-11-17
**Builds on:** 1.1.6 (reading commands, gut calls), 1.1.7 (settings `deny` rules are enforced), 1.2.3 (the permission prompt sits between PLAN and ACT).
**Source:** checked 2026-11-17 against code.claude.com/docs/en/permission-modes and /how-claude-code-works.

## What you'll learn
- What a permission mode is, and the main modes
- How modes and permission rules (allow / ask / deny) work together
- Which mode to use for which job, and the one to avoid

## Key terms
- **Permission mode:** the baseline for how often Claude Code asks you before acting.
- **Permission rule:** a specific setting (1.1.7) that always allows, always asks or always denies one kind of action. Rules sit on top of the mode.
- **Classifier:** in Auto mode, a separate model that reviews each action in the background and blocks risky ones.
- **Prompt fatigue:** clicking "Allow" so often that you stop reading what you're allowing. It defeats the point of prompts.
- **Checkpoint:** a snapshot Claude Code takes of a file before editing it, so the edit can be undone.
- **Isolated environment:** a sealed-off computer (a container or virtual machine) where mistakes can't reach your real files.

## The problem this solves
Too many prompts and you approve without reading. Too few and an agent can do damage before you notice. Modes let you choose the right level of supervision for the task, instead of one setting for everything.

## Explanation
**The modes** (names as shown in the desktop app's mode selector, under the prompt box in the Code tab)
| Mode | Runs without asking | Still asks or is blocked | Good for |
|---|---|---|---|
| **Manual** | Reading files | Edits, commands, network | Sensitive work; learning by watching every step |
| **Accept edits** | Reading, file edits, simple file commands (`mkdir`, `mv`, `cp`) | Other commands, paths outside the project | Work you'll review afterwards |
| **Plan** | Reading (it explores and proposes) | **Edits are blocked** until you approve the plan | Exploring something before changing it |
| **Auto** | Most things, with a classifier checking in the background | What the classifier blocks, plus your `ask` rules | Long tasks where you trust the direction |
| **Bypass permissions** | Everything | Almost nothing | **Only** sealed-off containers/VMs. **Never on your own PC.** |

The docs' own warnings:
- Auto mode "reduces permission prompts but does not guarantee safety". Use it for tasks "where you trust the general direction".
- Bypass "offers no protection against prompt injection or unintended actions". Use it only in isolated environments.

**Rules sit on top of modes.** "Deny rules block in every mode, including `bypassPermissions`" (docs). That's why the "never read `.env`" idea from 1.1.7 belongs in a deny rule: it holds whatever mode you're in. `ask` rules still force a prompt even in Auto.

**Undo has limits.** File *edits* are checkpointed and can be undone. But commands like `rm`, and anything that reaches the outside world (uploading a video, sending a message, calling an API), can't be undone by a checkpoint. Those are the actions to keep under Manual control or `ask` rules.

## Example from your projects
- First look at your old **trading-research** code → **Plan**: explore and explain, change nothing yet.
- Renaming 200 draft scripts inside a sandbox → **Accept edits** or **Auto**: low risk, and easy to check afterwards.
- Anything that **posts to YouTube/TikTok** or touches an account → **Manual**, plus an `ask` rule on the upload tool. It can't be undone, and a mistaken post can break platform rules.
- Running a random repo from a video → not Bypass. Read it first (1.1.5/1.1.6), or run it somewhere isolated.

## Hands-on exercise
1. **Observe:** in the Code tab, look at the mode selector under the prompt box. Which mode is this session in?
2. **Predict, then watch:** Claude will (a) read a file and (b) create a small file `note.txt` in `exercises\sandbox-1.2.5`. In your current mode, which one will ask you first?
3. (Optional) Switch to **Plan** in the selector, ask Claude to create `plan-test.txt`, and see what happens. Then switch back.
