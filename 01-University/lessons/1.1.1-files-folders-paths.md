# 1.1.1 Files, folders and paths
**Stage / Module:** 1 / 1.1 · **Status:** done · **Date taught:** 2026-11-16

## What you'll learn
- What files, folders and paths are
- Why the folder Claude Code starts in matters so much
- Why this program lives in `C:\Users\aidan\AI-Program` and not in `C:\WINDOWS\System32`

## Key terms
- **File:** a named container of data, such as a note, a script or an image. Its *extension* (`.md`, `.py`) hints at what's inside.
- **Folder (directory):** a container for files and other folders. "Directory" is the terminal word for the same thing.
- **Path:** a file's address. `C:\Users\aidan\AI-Program\HOME.md` reads as: drive C → folder Users → aidan → AI-Program → the file HOME.md.
- **Absolute path:** a full address starting from the drive (`C:\...`). It works from anywhere.
- **Relative path:** an address that starts from where you are now (`01-University\PROGRESS.md`).
- **Working directory:** the folder a terminal, or Claude Code, is "standing in" right now.
- **Home folder:** your personal folder, `C:\Users\aidan`. PowerShell shortcuts for it are `~` and `$HOME`.

## The problem this solves
Claude Code works on whatever folder you start it in. That folder decides:
1. which `CLAUDE.md` instructions load,
2. which files Claude sees first, and where it creates new ones, and
3. which project's memory and settings it uses.

Start it in the wrong folder and it gets the wrong instructions and the wrong memory, and it puts files in the wrong place.

## Explanation: what happened in our first session
You started Claude Code from `C:\WINDOWS\System32`. That's the default folder when PowerShell is opened as Administrator. System32 holds core Windows programs. It isn't empty: it holds thousands of files. Editing or deleting the wrong one can break Windows. So instead of building there, Claude created `C:\Users\aidan\AI-Program`, which is in your home folder, owned by you, and safe to change.

**Lesson:** always `cd` into your project folder *before* typing `claude`. And don't run your everyday terminal as Administrator. You rarely need it, and it gives every command, including ones an agent runs, power over the whole system.

## Example from your projects
Later you'll have `AI-Program`, `trading-research` and `content-agent` as separate folders, each with its own `CLAUDE.md`. Start Claude in `trading-research` and it follows the "research only, never trade" rules. Start it in `content-agent` and it follows the platform-posting rules. One folder per project is what keeps those rule sets from mixing.

## Hands-on exercise
Open a **normal** (not Administrator) PowerShell window. Press Start, type `PowerShell` and press Enter. Then run these commands one at a time:

1. `pwd`. This means "print working directory": *where am I?* You should see `C:\Users\aidan`. If you see `C:\WINDOWS\System32`, the window is running as Administrator. Close it and reopen it normally.
2. `cd AI-Program`. This means "change directory" into the program folder. It's a relative path, because you're already in `C:\Users\aidan`.
3. `pwd` again. It should now show `C:\Users\aidan\AI-Program`.
4. `ls`. This lists what's here. You should see `00-Inbox`, `01-University`, `CLAUDE.md`, `HOME.md` and the rest.
5. `cat HOME.md`. This prints the file's contents in the terminal.
6. `claude`. This starts Claude Code *here*. Ask it: "Where did we leave off?" It should answer from PROGRESS.md. That shows the memory system working.

### Bonus discovered during the exercise: encoding
`cat HOME.md` showed the diagram as junk characters (`â”Œâ”€â”€`). **Encoding** is the rulebook for turning the numbers stored in a file into characters. The file is **UTF-8**, but PowerShell 5.1 guessed an older Windows encoding. The fix is `cat HOME.md -Encoding utf8`. `-Encoding utf8` is a **parameter**, an extra instruction added to a command. Garbled symbols almost always mean an encoding mismatch, not corrupted data.
