# 3.C Stage 3 capstone: stack advisor and tool-review desk as repeatable processes
**Stage / Module:** 3 / capstone · **Status:** done · **Date taught:** 2026-11-20
**Builds on:** 1.2.7 (check sources), 1.5.6 (skip list), 3.1–3.4 (everything in STACK.md), 3.2 (skills).

## What you'll learn
How to turn "should I use this new tool?" from a gut feeling into a two-minute, repeatable check, so new videos can't pull you off the path.

## Key terms
- **Tool-review desk:** a process (here, the `/tool-review` skill) that researches one tool and gives a verdict: implement now, save for later, or ignore.
- **Stack advisor:** a process that keeps `STACK.md` true: what you use, why, what it costs, and what you deliberately skipped.
- **`$ARGUMENTS`:** in a skill, whatever you type after the command (e.g. `/tool-review n8n` → `n8n`).

## The problem this solves
Tool-chasing: every week there's a "must-have" tool. Without a process, you either install everything (cost, clutter, risk) or ignore everything (miss real wins).

## The two processes
1. **Tool-review desk:** type `/tool-review <name or link>` in AI-Program. It reads your stack and stage, checks official sources, fills the template (now with **Security** and **Platform-rules risk** rows), saves a file in `03-Optimization-Center/tool-reviews/`, and gives a one-line verdict. It never installs anything.
2. **Stack advisor:** `STACK.md` is the single source of truth. Monthly (`99-System/MAINTENANCE.md`): confirm each row is still true (installed, version, cost), move "later" items whose stage has arrived into a tool review, and add any new "deliberately not installed" decision.

## Example from your projects
You see a video: "This AI tool auto-posts to 10 TikTok accounts!" `/tool-review` → label "mostly hype", verdict "ignore": multi-account automation risks platform bans (content rules), and it gives an outside service your accounts.

## Hands-on exercise
Claude runs `/tool-review <tool>` in a fresh headless session that may read, search the web, and write **only** inside `tool-reviews/`. Then Claude checks the review file.
**Predict:** what verdict will it give?

## Knowledge check (2 questions)
1. Why does the desk never install anything itself?
2. A review says "implement now" but STACK.md already has a tool doing the same job. What's wrong?

## Concept notes created or updated
None.

## Answers
1. Reviewing and installing are separate decisions: you approve installs (and installs are your hands-on part). It also keeps the desk safe to run on any link.
2. Overlap: the rule is "implement now" only if nothing you have already covers the need. The review should say "ignore" or explain why replacing the old tool is worth it.
